# Asset Pipeline

Tiny Vials uses a **hybrid** approach: procedural geometry for anything that
needs per-patient variation or physics-relevant collision, and (eventually)
authored GLB models for static hand-held instruments where visual fidelity
matters more than parametric control.

## Status: 13 real registrations, all still on procedural builders

`rendering/modelRegistry.js` implements the full load → cache → fallback →
instance pipeline. `src/venipuncture/staging/supplyModels.js` registers the
13 `supply.*` ids the venipuncture gameplay actually uses — glove box,
tourniquet, alcohol prep packet, multisample needle, tube holder, gauze,
bandage, collection tube, sharps container, cotton balls, syringe, urine
container, tray — each with `url: null` and a detailed procedural builder.

That means the game currently ships zero third-party geometry and still shows
recognisable clinical equipment. Adding a licence-cleared `.glb` is a one-line
change (fill in the `url`); the fallback stays in place and takes over
automatically if the file is ever missing or corrupt. See
`docs/ASSET_SOURCES.md` for what has to be recorded before any external file
enters the repository.

Everything is modelled at real clinical scale in metres (a 13 × 75 mm tube is
`0.013 × 0.075`), so these props can be reused next to a full-size arm in later
branches without rescaling.

## The registry API

```js
import { registerModel, preloadModels, createModelInstance } from "./rendering/modelRegistry.js";

registerModel({
  id: "needleHolder",
  url: "assets/models/needle-holder.glb",   // omit or leave null if no GLB yet
  fallback: createNeedleHolderFallback,      // () => THREE.Object3D, using box()/cyl()/sph() from rendering/materials.js
});

await preloadModels(["needleHolder", "multisampleNeedle", "tourniquet"], (done, total, id) => {
  // optional progress callback, e.g. for a loading bar
});

const holder = createModelInstance("needleHolder"); // safe to add to the scene; clone() per call
```

Behavior:
- If `url` is set and the GLB loads successfully, that becomes the cached
  template.
- If `url` is missing, or the GLB fails to load, `registerModel`'s
  `fallback()` factory is called instead and **that** becomes the cached
  template — the rest of the game never needs to know which happened.
- `createModelInstance(id)` returns a `.clone(true)` of whichever template is
  cached — geometry and materials are shared across instances (correct and
  efficient for static decor/props; a future prop needing per-instance
  material tinting would clone its own materials after `createModelInstance`
  returns).
- `disposeModel(id)` / `disposeAllModels()` free geometry/material GPU memory
  when a model registry entry is no longer needed.

## What's procedural vs. what will be a GLB (Phase 1+)

**Procedural (built with `rendering/materials.js`'s `box()`/`cyl()`/`sph()`,
or a dedicated builder function)** — anything needing per-patient variation,
physics-relevant collision, or deformation:

- The arm itself (varies by patient body width/height already — see
  `game/encounter.js`'s `makeAppearance()`)
- Skin (tone varies per patient)
- Veins (median cubital / cephalic path varies per site scenario —
  `game/encounter.js`'s `makeSiteScenario()`)
- The brachial artery (must pulse, must be a *hazard* the player can
  mis-target — needs to be real geometry with real position, not a sprite)
- The tendon (same — a real collision volume the player can mistake for a
  vein)
- Per-patient anatomy variation generally (age category, body width/height)
- Palpation deformation (the skin/vein response to the player pressing —
  needs live geometry, not a static mesh)
- Needle collision volumes for the future 3D insertion interaction (needs to
  match the procedural vein geometry exactly, which only works if both are
  generated by the same code)

**GLB assets (static instruments, no per-patient variation)**:

- The multi-sample needle
- The tube holder
- Needle caps
- The safety/retraction device
- Collection tubes (color is a material swap, not a geometry change — one
  GLB, tinted per tube type)
- The tourniquet
- Gauze
- Alcohol prep supplies
- The bandage
- The sharps container

## Why this split, and not "everything procedural" or "everything GLB"

Everything procedural would work but caps visual fidelity for the hand-held
instruments where players look closely and fine detail matters most (the
needle bevel, the tourniquet's clasp). Everything GLB would work for the
instruments but is actively wrong for the arm/veins/artery — those need to
be regenerated per-patient with correct relative positioning for collision
and palpation to work at all, which is what procedural generation is for.

## Adding a real asset later

1. Drop the `.glb` in `public/assets/models/` (served at
   `/PhlebLearn/assets/models/...` in production, `/assets/models/...` in
   dev).
2. Add its `url` to the existing `registerModel()` call — no other code
   changes, since every caller already goes through `createModelInstance()`.
3. Keep the `fallback` factory in place. A missing or corrupt GLB should
   never break the scene; it should silently degrade to the procedural
   placeholder (this is enforced by `modelRegistry.js`'s `loadOne()`, not by
   caller discipline).
